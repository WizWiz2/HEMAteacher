# Признаки footwork_v1

Сравнение идёт не по пикселям, а по признакам уже нормализованного скелета.
Пороги и веса лежат в `data/profiles/footwork_v1.yaml`. Менять их можно без правки кода.

## Система координат

После нормализации:

- начало — середина бёдер;
- **+X** — вперёд, туда же, куда смотрит нос;
- **+Y** — вверх (ось кадра перевёрнута);
- **Z** — глубина MediaPipe, примерно в том же масштабе, что и X; с одной камеры это шумная ось;
- единица длины — **длина корпуса** (середина плеч → середина бёдер), одна на всю запись.

Масштаб считается по всей записи, а не по каждому кадру. Иначе сгиб колена сам себя вычитал бы из измерения.

Если человек в кадре смотрит в другую сторону, последовательность отзеркаливается так, чтобы нос оказался в +X. Левая и правая стороны остаются анатомическими: это метки MediaPipe, они не меняются местами.

Стратегия масштаба настраивается: `torso_length` (по умолчанию), `shoulder_width`, `hip_width`, `leg_length`. Для вида сбоку ширина плеч в кадре почти нулевая, поэтому для MVP оставлена длина корпуса.

## Признаки на каждый кадр

| id | единица | смысл |
| --- | --- | --- |
| `left_ankle_x`, `right_ankle_x` | длина корпуса | стопа вперёд/назад относительно таза |
| `left_ankle_y`, `right_ankle_y` | длина корпуса | высота стопы, + вверх |
| `left_heel_x`, `right_heel_x` | длина корпуса | пятка вперёд/назад |
| `left_toe_x`, `right_toe_x` | длина корпуса | носок (`foot_index`) вперёд/назад |
| `foot_distance` | длина корпуса | расстояние между лодыжками в плоскости XY |
| `lateral_foot_distance` | длина корпуса | модуль разницы Z лодыжек, боковой разнос; оценка грубая |
| `pelvis_height` | длина корпуса | насколько таз выше середины лодыжек. После переноса таз в нуле, поэтому это `-mean(ankle_y)`, а не высота над полом комнаты |
| `left_knee_angle`, `right_knee_angle` | градусы | угол в колене, бедро–колено–лодыжка. 180° — прямая нога |
| `left_hip_angle`, `right_hip_angle` | градусы | угол в тазобедренном, плечо–бедро–колено |
| `torso_angle` | градусы | наклон линии «таз → плечи» от вертикали. Плюс — вперёд, в +X |
| `knee_over_foot_left`, `knee_over_foot_right` | длина корпуса | `knee_x - ankle_x`. Плюс — колено впереди стопы |
| `left_leg_extension`, `right_leg_extension` | длина корпуса | расстояние бедро–лодыжка в плоскости XY |
| `shoulder_offset` | длина корпуса | насколько середина плеч уехала вперёд от таза. В профиль не входит, считается для отладки |

`pelvis_bounce` — не покадровый признак, а стандартное отклонение `pelvis_height` на активной части шага. В профиле у него `reduce: std`.

## Фазы

Фазы режутся по эталону, попытка смотрится через выравнивание по времени.

- `preparation` — до заметного движения стоп;
- `stride` — от старта до кадра с наибольшим расстоянием между стопами;
- `landing` — от этого кадра до падения скорости стопы;
- `completion` — до конца ролика;
- `overall` — весь активный кусок, для признаков вроде разброса высоты.

Если скорость так и не поднялась выше порога, ролик делится на четыре равные части с теми же именами.

## Схожесть

Для каждого признака с весом больше нуля:

`схожесть_признака = max(0, 1 - средняя_|разница| / major_threshold)`

Общая схожесть — взвешенное среднее, умноженное на 100. На экране это **схожесть с этой записью**, не оценка техники.

В замечания попадают только `warning` и `major`, не больше трёх, по одному на признак. Порядок: тяжесть × вес × доля фазы.

## Выравнивание по времени

DTW считается по `dtw_features` профиля. Перед расстоянием каждый канал делится на разброс эталона. Сравнение дальше не знает, что внутри именно DTW: его можно заменить, не трогая замечания.
